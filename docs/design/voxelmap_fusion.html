Voxelmap Fusion vs Sonar 3D Reconstruction Comparison

1. Overview

This document compares the sonar-based 3D mapping algorithms between voxelmap_fusion (2024.02.05) and sonar_3d_reconstruction packages.

Aspect

voxelmap_fusion

sonar_3d_reconstruction

ROS Version

ROS1 (kinetic)

ROS2 (humble)

Language

Data Structure

Dense Voxel Grid

Sparse Octree

Probability Model

Weighted Average

Log-Odds Bayesian

Coordinate Transform

Spherical Segment

Ray-based

2. Core Algorithm Comparison

2.1 Probability Update Methods

voxelmap_fusion: Weighted Average

# Voxel.py:71-72
old_OP_scaled = (num_sonar_constraints + num_optical_constraints) * old_OP
new_OP = (old_OP_scaled + OP) / (num_sonar_constraints + num_optical_constraints + 1)

Characteristics:

  • Treats all constraints equally

  • Recalculates average with each new observation

  • Each constraint has equal influence (1/N)

  • Tracks constraints per voxel (enables backtracking)

Advantages:

  • Intuitive and easy to understand

  • Constraint tracking enables update propagation

  • Less sensitive to outliers

Disadvantages:

  • New observation influence decreases with count

  • Slow convergence

  • Excessive weight on initial observations

sonar_3d_reconstruction: Log-Odds Bayesian (IWLO)

# 3d_mapper.py
log_odds_new = log_odds_old + delta_log_odds
probability = 1 / (1 + exp(-log_odds))

Characteristics:

  • Converts probability multiplication to addition in log space

  • Each observation contributes independently

  • Clamping limits extreme values (-10 to 10)

  • Adaptive scaling reduces noise

  • Intensity weighting modulates update strength

Advantages:

  • Fast convergence

  • Update strength independent of observation count

  • Mathematically robust probability model

  • Suitable for real-time processing

Disadvantages:

  • Can be sensitive to outliers

  • Cannot track individual observations

2.2 Occupancy Value Assignment

voxelmap_fusion: Binary

# SonarConstraint.py:277, 286
# Occupied: OP = 1.0
# Empty: OP = 0.0

Issue:

  • Does not utilize sonar intensity values (0~1)

  • Cannot distinguish strong vs weak reflections

  • High threshold dependency

sonar_3d_reconstruction: Intensity-Based (IWLO)

# probability_updater.cpp:373-380
if (intensity > intensity_threshold_) {
    delta_L = log_odds_occupied_ * w_intensity * alpha_n * adapt_scale;
} else {
    delta_L = log_odds_free_ * alpha_n * adapt_scale;
}

Improvement:

  • Intensity is converted to weight via sigmoid

  • Stronger reflections → larger log-odds updates

  • More precise probability estimation

2.3 Data Structures

voxelmap_fusion: Dense Voxel Grid

# VoxelMap.py:81-102
voxels = []  # Store all voxel objects
voxel_positions = np.zeros((num_X * num_Y * num_Z, 3))

for i in range(num_voxels_X):
    for j in range(num_voxels_Y):
        for k in range(num_voxels_Z):
            voxels.append(Voxel())  # Create all voxels

Memory Usage:

  • 81 x 81 x 81 = 531,441 voxels

  • Each Voxel object: ~200+ bytes (including lists, arrays)

  • Total: ~100MB or more

Issues:

  • Unobserved regions also occupy memory

  • O(N³) memory growth with resolution increase

  • Long initialization time

sonar_3d_reconstruction: Sparse Octree

// ProbabilityUpdater uses hash map
std::unordered_map<std::string, double> voxels_log_odds_;

Memory Usage:

  • Only observed voxels stored

  • 29~93x memory reduction (experimental results)

  • Dynamic boundary expansion

Advantages:

  • Memory efficient

  • Supports unlimited map size

  • Fast initialization

2.4 Coordinate Transformation

voxelmap_fusion: Spherical Segment

# SonarConstraint.py:138-150
R = Roll Matrix (X-axis rotation)
P = Pitch Matrix (Y-axis rotation)
Y = Yaw Matrix (Z-axis rotation)
T = Tilt Matrix (sonar tilt)
Rot = Y @ P @ R @ T

# Check if voxel is inside spherical segment
if voxel_vector @ Rot @ boundary_normal > 0:
    continue  # Outside FOV

Characteristics:

  • Models each pixel as spherical segment

  • Half-plane tests for FOV determination

  • Accurate geometric verification

Advantages:

  • Mathematically precise FOV check

  • Supports arbitrary sonar orientations

Disadvantages:

  • Creates individual segment per pixel (inefficient)

  • O(N × K) complexity (N=pixels, K=voxels)

sonar_3d_reconstruction: Ray-based

# 3d_mapper.py:544-551
x_sonar = range_m * cos(vertical_angle) * cos(bearing_angle)
y_sonar = -range_m * cos(vertical_angle) * sin(bearing_angle)
z_sonar = range_m * sin(vertical_angle)

pt_world = T_sonar_to_world @ pt_sonar

Characteristics:

  • Ray tracing along each bearing

  • Computes vertical spread

  • Pre-computed transformation matrices

Advantages:

  • Intuitive ray model

  • Full vertical aperture support

  • Efficient ray processing

4. Advanced Features of voxelmap_fusion

4.1 Constraint Tracking System

# Voxel.py:16-21
num_sonar_constraints = 0
sonar_constraint_IDs = []  # [SC_ID, col_ID, row_ID]
sonar_constraint_occupancy_probabilities = []

Applications:

  • Track which observations affected each voxel

  • Enable reverse updates when observations are removed/modified

  • Analyze sensor contribution in multi-sensor fusion

4.2 State Change Detection

# VoxelMap.py:357-373
if (old_OP <= thres_empty and new_OP > thres_empty) or \
   (old_OP > thres_empty and new_OP <= thres_empty) or \
   (old_OP < thres_occ and new_OP >= thres_occ) or \
   (old_OP >= thres_occ and new_OP < thres_occ):
    state_changed = True

Applications:

  • Detect occupied/unoccupied state transitions

  • Performance improvement via selective updates

  • Map change event generation

5. Mathematical Formula Comparison

5.1 Probability Update Formulas

voxelmap_fusion (Weighted Average): $$P_{new} = \frac{n \cdot P_{old} + P_{obs}}{n + 1}$$

Where:

  • $n$ = existing constraint count

  • $P_{old}$ = existing occupancy probability

  • $P_{obs}$ = new observation’s occupancy probability

sonar_3d_reconstruction (IWLO Log-Odds): $$L_{new} = L_{old} + \Delta L$$ $$\Delta L = L_{occ} \times w(I) \times \alpha(n) \times scale$$ $$P = \frac{1}{1 + e^{-L}}$$

Where:

  • $L$ = log-odds = $\log\frac{P}{1-P}$

  • $w(I)$ = intensity weight from sigmoid transformation

  • $\alpha(n)$ = learning rate that decays with observation count

  • $\Delta L$ = log-odds change per observation

6. Conclusion

voxelmap_fusion Advantages (Consider Adopting)

  1. Constraint Tracking: Observation history management and backtracking

  2. State Change Detection: Efficient selective updates

  3. Spherical Segment Verification: Accurate FOV checks

sonar_3d_reconstruction Advantages (Maintain)

  1. IWLO Probability Model: Fast convergence, robust mathematical foundation, intensity utilization

  2. Sparse Octree: Memory efficiency

  3. C++ Backend: Real-time processing performance

  4. ROS2 Integration: Modern robotics system compatibility
